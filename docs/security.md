# Security

The threat model of Elysion, the result of a review of the token flows, the internal API and the edge, and what is known to be wrong. It
belongs to PBI #677 (task #678). To report a vulnerability, read [SECURITY.md](../SECURITY.md).

**Scope and date.** The review was done on 2026-10-10 against `main` plus the security headers of #680 (commit `79aae16`), by reading the code and by
attacking the running compose stack (`pnpm dev:stack`, Traefik on port 80, Keycloak on the loopback port 8081, the users `dev1` and `dev2`).
Every row of the [review table](#the-review) says what was tried and what came back; the commands can be run again on a stack of your own. The
Helm chart was read, not run. This is a review of a pre-release by its developers, not an audit by a third party.

The compose stack is a demo (Keycloak in `start-dev`, development secrets, plain HTTP, [ADR 0028](adr/0028-production-topology-tls-and-keycloak.md)).
What follows judges the **design** and the **code**, and says "demo only" where a finding exists only because of a development default.

## Threat model

### Assets

| Asset                            | Where it lives                                                                                | Why it matters                                                                                                    |
| -------------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Board content                    | Yjs state in Postgres (`BoardDocuments`, `bytea`), in memory in the realtime service          | The product. Confidentiality (who may read) and integrity (who may write)                                         |
| Board images                     | The object store (RustFS in the stack), behind the business backend                           | Same as the content                                                                                               |
| Membership and roles             | Postgres (`BoardMemberships`, `RoomMemberships`)                                              | They decide who may read and write; the WS token copies the role at connect                                       |
| Templates                        | Postgres; private to their owner, built-in ones are public                                    | Content of the owner                                                                                              |
| Identities                       | Keycloak (its own database): passwords, refresh tokens, the realm                             | Everything else follows from them. Services never see a password                                                  |
| Access token                     | The browser's memory (Keycloak JWT, 5 minutes, audience `elysion-bff`)                        | Acts as the person on every `/api` call                                                                           |
| Refresh token                    | The browser (30 minutes of session idle in the demo realm)                                    | Mints new access tokens                                                                                           |
| WS token                         | The browser, the URL of one WebSocket upgrade (HS256, 60 s, one board, one role)              | Opens one board with the role it carries                                                                          |
| `WS_TOKEN_SECRET`                | BFF and realtime environment                                                                  | Whoever has it mints a WS token for any board with any role                                                       |
| `INTERNAL_API_SECRET`            | Realtime and business backend environment                                                     | Whoever has it reads, writes and deletes any board document ([ADR 0017](adr/0017-internal-api-authentication.md)) |
| Database, Valkey, S3 credentials | Environment of the services                                                                   | Direct access to everything above                                                                                 |
| Logs                             | stdout, optionally the log viewer ([ADR 0025](adr/0025-structured-logging-and-log-viewer.md)) | Must hold no token, header or query string                                                                        |

### Entry points

| Entry point                                            | Reachable from                                                           | Authentication                                                                                                          |
| ------------------------------------------------------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| `http://<host>/` (frontend, nginx)                     | Anybody who reaches the edge                                             | None (the app must load to start the login). Static files and the security headers                                      |
| `/api/*` (BFF, through Traefik)                        | Anybody who reaches the edge                                             | Access token, checked by Traefik's `forwardAuth` (`GET /api/auth/verify`) and again by the BFF and the business backend |
| `POST /api/csp-report`                                 | Anybody who reaches the edge                                             | **None, on purpose** (a browser sends a report without a token); rate limited, body limited                             |
| `/yjs` (realtime, WebSocket)                           | Anybody who reaches the edge                                             | WS token in the query string, checked at the handshake only; no rate limit                                              |
| `/health` of the services                              | The compose network (not routed)                                         | None                                                                                                                    |
| `/metrics` of each service                             | The compose network (not routed)                                         | None                                                                                                                    |
| Traefik `:8082` (metrics), `:8080` (dashboard and API) | The compose network; `:8080` also the host with `docker-compose.dev.yml` | None                                                                                                                    |
| `/internal/*` of the business backend                  | The compose network (not routed)                                         | Service token signed with `INTERNAL_API_SECRET`                                                                         |
| Keycloak `:8081` (login, admin console)                | The host's loopback (`KEYCLOAK_BIND`)                                    | Keycloak's own; the demo admin is `admin` / `admin`                                                                     |
| Valkey `:6379`, Postgres `:5432`, S3 `:9000`           | The compose network                                                      | **None** (Valkey), the password `elysion` (Postgres), development keys (S3)                                             |
| Browser: imported `.excalidraw` files, templates       | The user's own tab                                                       | The person chose the file                                                                                               |

### Trust boundaries

1. **The Internet and the edge.** Traefik is the only published port (80). Everything behind it is reached through a router with a middleware chain
   (`security-headers`, `cors`, `rate-limit`, `bff-auth` on `/api`). No `X-Forwarded-*` header of a caller is trusted.
2. **The browser and the page.** The page is trusted to hold the access token in memory; the Content-Security-Policy of #680 is the second line
   against script injection. A board is data from other people: it is rendered by Excalidraw and never executed.
3. **The compose network (the cluster).** Inside it, services trust their network: Valkey has no password, the metrics and health routes are open, the
   backend is protected by its own tokens only. **A workload on this network is as good as inside.** The Helm chart narrows this with network policies;
   the compose file does not and is documented as a demo.
4. **The service to service tokens.** Each service checks the token it acts on: the business backend validates the Keycloak JWT itself and
   authorizes by membership; `/internal` accepts only the realtime service's token (another authentication scheme, another issuer and audience).

### Attacker positions and what each can do

| Position                                | Can do                                                                                                                                                                                                                                                                              | Cannot do                                                                                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **Anonymous, from the Internet**        | Load the app; post CSP reports (rate limited); open unlimited WebSocket upgrades that are closed with 4401 at once; read the public parts of Keycloak (login page, JWKS).                                                                                                           | Call any `/api` route (401 at the edge, the BFF and the backend), reach `/internal` or `/metrics`, open a board, forge an identity header. |
| **A signed-in person (any board role)** | Everything their roles allow, on the boards they are a member of: viewers read, editors write, owners administer. Create boards and templates (no per-user quota, [finding](#confirmed-findings)).                                                                                  | See another board, template or room; get a WS token for a board without a role (403).                                                      |
| **A removed or demoted member**         | Keep their open WebSocket for up to `MEMBERSHIP_RECHECK_MS` (15 s) ([finding F1](#confirmed-findings), fixed in #772), then the socket is closed or lowered. Cannot fetch a new WS token (403) or call `/api` for the board.                                                        | Reconnect after the connection drops.                                                                                                      |
| **Stolen access token**                 | Everything the person can do through `/api` for up to 5 minutes (the token is not revocable: services validate the signature and the expiry, nothing else), and exchange it for WS tokens for the person's boards. No refresh.                                                      | Anything after expiry; access to `/internal` (another scheme, 401 verified).                                                               |
| **Stolen refresh token**                | Mint access tokens for the rest of the session (30 minutes idle, up to the SSO maximum). The realm decides; services do not see it.                                                                                                                                                 | n/a (Keycloak revokes it with the session).                                                                                                |
| **Stolen WS token**                     | Open one board with the role in the token for the remaining seconds of its life; the token was not single-use (two sockets with one token both opened, fixed in #772) and the socket stays open as long as the person has a role (checked every 15 s).                              | Open another board (4403), keep the token past 60 s for a new connection, call `/api`.                                                     |
| **Leaked `WS_TOKEN_SECRET`**            | Mint a WS token for any board, any role, any `sub` (confirmed: a forged owner token opened a board). The identity is not looked up. The realtime service trusts the claim.                                                                                                          | Read the database or call the backend: the WS token is no credential there.                                                                |
| **Leaked `INTERNAL_API_SECRET`**        | Read, overwrite and delete the stored document of any board through `/internal` (confirmed from the compose network), and store a document for a board id that does not exist. Users' content is lost or replaced without a trace.                                                  | Use `/api`, and no user identity (no `sub` is checked).                                                                                    |
| **A position on the compose network**   | Everything above and more: read `/metrics` of all services; read Traefik's API on `:8080`; talk to Valkey without a password and **inject Yjs updates into any board** (confirmed, [F4](#confirmed-findings)); reach Postgres with the demo password and RustFS with the demo keys. | Be a user: `/api` and `/internal` still want a token (with the two secrets above it can make one).                                         |
| **Host access to the docker socket**    | Traefik mounts it read-only; read-only still lets a process that controls Traefik list every container and its environment (secrets). A compromised Traefik is a compromised host.                                                                                                  | n/a                                                                                                                                        |
| **Keycloak admin**                      | Everything: any user, any role, any token.                                                                                                                                                                                                                                          | n/a. The demo's `admin` / `admin` is bound to the loopback.                                                                                |

The three token flows follow [identity](specs/identity.md) and [ADR 0017](adr/0017-internal-api-authentication.md). The design is sound in the
properties the review looked for: no service trusts an identity header (the BFF only _sets_ `X-Auth-User-Id`, nothing reads it), every service validates
its token itself, a WS token is bound to one board, and `/internal` has its own scheme. Its weakness is **time**: the WS token and the role in it are checked once.

## Confirmed findings

Severity is for a production deployment; "demo only" says when the cause is a development default. Each becomes a `[Bug]` issue under #677.

| ID  | Finding                                                                                                                                               | Severity | Area                    | Fix                                                                                                                                                                                                                                                                                                     |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | An open WebSocket keeps its role after the membership was removed, the role lowered or the board deleted (#772)                                       | High     | `area:realtime`         | **Fixed in #772:** the realtime service asks the backend every 15 s who still has a role and closes (4403) or lowers the socket; a WS token has a `jti` and opens one socket. ## Not a finding, because

- **The WS token in the URL.** It is in no log (Traefik drops the query, the services log the reason only), `Referrer-Policy: no-referrer` and the upgrade
  is not a navigation, it lives 60 s and opens one board. The residual risk is a reverse proxy or a load balancer **in front of Traefik** that logs full URLs:
  configure it not to log the query of `/yjs` (this is a deployment note for [self-hosting](self-hosting.md)).
- **`X-Auth-User-Id` set by a client.** Traefik replaces it on the forwarded request, and the BFF does not read it: it takes the identity from the token's claims.
- **`/internal` at the edge.** Not routed; falls to the frontend. The user's token does not open it.
- **`X-Forwarded-For` and the rate limit.** Traefik does not trust it and counts the peer. A reverse proxy in front needs Traefik's `forwardedHeaders.trustedIPs`
  and an `ipStrategy` on the limit, or all users share one budget; that is a topology decision for [ADR 0028](adr/0028-production-topology-tls-and-keycloak.md).
- **Template `Scene` of 5 MB.** Bounded on both ends, parsed once for validation. Templates are private to the owner, so a hostile scene reaches only its author.
- **Imported files.** The user's own choice; Excalidraw restores the data and never evaluates it, SVG images are refused, and the CSP forbids inline script.
  The consequence of a huge file is the size problem of F2, not a code execution.
- **Cross-site WebSocket hijacking.** There is no ambient credential (no cookie); the token must be known.
- **Keycloak admin `admin` / `admin`, the password grant, `sslRequired: none`, no TLS, development secrets in `docker-compose.yml`.** The demo is documented as such
  ([SECURITY.md](../SECURITY.md), [self-hosting](self-hosting.md), [ADR 0028](adr/0028-production-topology-tls-and-keycloak.md)); the admin console is on the loopback.
- **Open `/metrics` and `/health` on the network.** They are scrape targets, not published; the network policies of the chart restrict them to the monitoring namespace.
  They hold counts and route names, no user data or secrets.
- **Postgres and Valkey start as root.** Their entrypoints drop to the `postgres` and `valkey` users (`ps` shows it); only the entrypoint is root.
- **An access token that works until it expires.** The design (stateless validation, 5 minutes, [ADR 0014](adr/0014-keycloak-identity-provider.md)) accepts it; a
  stolen token is a 5-minute problem. The long-lived socket is not the same thing (F1).
- **Voting is not secret from the server.** Documented ([ADR 0020](adr/0020-facilitation-state.md), README).
- **No HSTS or TLS in the demo.** `HSTS_MAX_AGE` is for deployments with TLS.

(`braces`, stack exhaustion on deeply nested patterns, no patched release). It is reached as `@excalidraw/excalidraw > sass > chokidar > braces`, Sass's
file watcher, which the built bundle does not run and no service loads. It is looked at again with every Renovate update of Excalidraw
([ADR 0024](adr/0024-renovate-for-dependency-updates.md)). The image scan's allowlist is `.trivyignore`; it is empty, and an entry needs a reason and a date.

## Scanning in CI

Three checks run on every pull request and on `main` (the `ci.yml` jobs `scan` and `audit`, and `codeql.yml`; a release waits for the first two):

- **Image scan:** each of the four images is built as a release would publish it and scanned by Trivy. A CRITICAL vulnerability that has a fix fails the check; HIGH ones are listed in the log. The allowlist is `.trivyignore` (empty; an entry needs a reason and a date above it). Base images change without a commit of ours: a red scan on an untouched branch means rebuild or take the update. Reproduce: `docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy image --severity CRITICAL --ignore-unfixed <image>`.
- **Dependency audits:** `pnpm audit --prod --audit-level high` (the allowlist is `auditConfig.ignoreGhsas` in `pnpm-workspace.yaml`, see "Accepted advisories") and `dotnet list package --vulnerable --include-transitive` (any hit fails).
- **CodeQL** for TypeScript and C#, on pull requests, on `main` and weekly; results are under Security > Code scanning.

Renovate keeps closing the gap ([ADR 0024](adr/0024-renovate-for-dependency-updates.md)). The day this was set up the scan found no CRITICAL vulnerability in any image and one HIGH (libtiff in the frontend's Alpine base, fixed upstream).

## Re-running the review

Everything above can be repeated on a running stack. The scripts used were small Node programs on top of `ws` and `yjs` (the realtime service's dependencies):
open a socket with a WS token, change the membership with `DELETE /api/boards/<id>/members/<userId>`, write to the Yjs map and read the board from a second
connection. After F1 is fixed, the first of these must end with the socket closed within seconds of the `DELETE`. Delete the boards and templates a run creates.
